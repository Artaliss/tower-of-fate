## 1. Life progression: tick, เวลา, ความเร็ว

- **1 ปี = 1 รอบ `planYear()` แล้วจบด้วย `endYear()`** ระหว่างปี ตัวแปร `S.t` เดินจาก 0 ไป 1 แบบ real-time
- ความยาวของ 1 ปีกำหนดจากระยะเวลาทั้งชีวิตที่ผู้เล่นเลือกไว้ (ตัวเลือก 30 / 60 / 90 นาที ค่า default คือ 60):
  ```js
  yearSec: clamp(paceMin * 60 / Math.max(lt.e0, 60), 12, 120)   // e0 = อายุขัยคาดเฉลี่ยของประเทศ+เพศ
  ```
  ดังนั้นชีวิตยาวราวอายุขัยเฉลี่ยจะใช้เวลาจริงประมาณ paceMin นาที (ปีละ 12–120 วินาที)
- ตัวคูณความเร็ว `SPEEDS = [1, 2, 4, 8, 12, 16]` จำค่าไว้ใน prefs มี hint ขึ้นว่า "ถ้ามีการตัดสินใจสำคัญ เวลาจะหยุด"
- `tick(dt)`: `S.t += dt*speed/yearSec` แล้วยิงทุกอย่างใน `S.queue` ที่ `at <= t` ออกตามลำดับ ถ้ายิงแล้วเกิด `S.pending` (มี decision ค้าง) เวลาจะหยุด
- **`planYear()` วางตารางของปีนั้นไว้ล่วงหน้า:**
  ```js
  const n = S.age < 1 ? 2 : (S.age < 6 ? 2 : 3);           // feed event 2–3 ชิ้น/ปี
  for (i<n) ts.push(0.08 + (i + rnd()*0.8)/n * 0.86);         // กระจายเวลาแบบ jitter
  for (at of ts) { ev = chooseFeed(used); queue(at,'ev',ev) }
  decs.slice(0,2).forEach((d,i)=>queue(0.3+i*0.3+rnd()*0.15,'dec',d.id,d.p)); // decision ไม่เกิน 2/ปี
  if (MILESTONE_AGES.includes(S.age)) queue(0.03,'ms','survive'); // อายุ 1,5,15,30,50,65,80,90,100
  ```
  มี history event (`'hist'`) และ economic shock จาก `nowPlan()/eraPlan()` ที่ถูก queue เพิ่มเข้ามาได้อีก
- **`endYear()` คือจุดที่ simulation จริงทำงาน** ขั้นตอนตามลำดับ:
  1. นำเวลาที่ผู้เล่นตั้ง focus ไว้ (`S.fT`) มาถ่วงน้ำหนักแล้วปรับ stat
  2. งานอดิเรก ความรู้ โรงเรียน การเงิน
  3. stat แต่ละตัวค่อยๆ เคลื่อนเข้าหาค่าเป้าหมายแบบ lerp (สูตรดูหัวข้อ 6)
  4. เรียกระบบย่อยประมาณ 60 ตัวตามลำดับ: `familyYear, petYear, faithYear, lottoYear, hivYear, tbYear, darkYear, mindYear, sickYear, drugYear, lawYear, kinYear, adoptYear, tradYear, soldierWarYear, rareYear, eggYear …` ระหว่างทางเช็ค `if (S.phase !== 'life') return;` เป็นระยะ เพราะระบบย่อยฆ่าตัวละครได้
  5. บันทึก snapshot ของปีลง `S.years[]` เพื่อใช้วาดกราฟและหน้าสรุปตอนจบ
  6. ทอยตาย (หัวข้อ 5)
  7. `S.age++` แล้วเรียก `planYear()` ของปีถัดไป

## 2. Event/content system

### 2.1 Feed events (`EVENTS`, ประมาณ 236 ตัว: 188 ตัวใน array หลัก บวก WARM/OLD_JOYS ที่ push เพิ่ม)
รูปแบบข้อมูล:
```js
{ id:'fam_trip', a:[5,14],                       // ช่วงอายุ
  c: () => S.q>=4 && (C().ppp>10000 || S.q===5), // เงื่อนไข: ฐานะครอบครัว (q 1-5), รายได้ประเทศ, flags ฯลฯ
  w: 0.8,                                        // น้ำหนัก (เป็น function ก็ได้)
  gap: 4,                                        // cooldown (ปี)
  rep: 1,                                        // ยอมให้ซ้ำได้ (โดนลดน้ำหนักน้อยกว่า)
  prison: 'nk',                                  // บริบทเฉพาะ (คุก ฯลฯ)
  run: () => { eff({h:3,so:1}); return { t: L`...`, k:'warm', f: L`fact...` }; } }
```
- `c()` ใช้ตรวจ flag, ประเทศ (`C().id`, `C().p` = ภูมิภาค ssa/sa/eap/lac/mena/eca/hi), ปีปฏิทิน, ครอบครัว, งาน และอื่นๆ
- event ที่ต้องทอยก่อนใช้ `yearRoll(id,p)`: ทอยความน่าจะเป็นจริงครั้งเดียวต่อปีแล้ว cache ผลไว้ เช่น `kidsick` ใช้ความน่าจะเป็น `0.06 + u5/250` คูณด้วยตัวคูณฐานะ
- `run()` คืนค่า `{t, k, f}` โดย k คือชนิดของ log ใช้กำหนดสีใน feed (`ev`, `big`, `bad`, `warm`, `loss`, `note`, `dec`, `ms`, `death`, `comp`)

**การเลือก event (`chooseFeed`):**
```js
if (age นอก ev.a || used.has(id)) skip; if (!evFits(ev) || (ev.c && !ev.c())) skip;
if (ev.gap && S.flags['ev_'+id]!=null && S.age - S.flags['ev_'+id] < ev.gap) skip;
wt = ev.w(); if (S.recent.includes(id)) wt *= ev.rep ? 0.5 : 0.08;   // recent = 14 event ล่าสุด
return wpick(w);   // สุ่มแบบถ่วงน้ำหนัก
```
`evFits` ใช้กรองตามบริบทใหญ่ เช่น อยู่ในคุก ไปเรียนต่างประเทศ กำลังรับราชการทหาร หรือมีความพิการบางแบบ โดยมีชุดข้อห้าม `STUDY_SKIP`, `SERVICE_SKIP`, `BARRACKS_SKIP`, `FAR_SKIP`

### 2.2 Year systems (`xxxYear()` ประมาณ 60 ตัว)
เนื้อหาส่วนใหญ่ของเกมอยู่ในกลุ่มนี้ ไม่ได้อยู่ใน EVENTS แต่ละตัวเป็น state machine ย่อยที่ใช้อัตราจริงของประเทศ ตัวอย่าง:
- `vnYear`: ถ้าเป็นชายและกำลังรับราชการในช่วงปีที่ประเทศส่งทหารไปเวียดนาม/อัฟกานิสถาน จะมีโอกาสถูกส่งไปรบและตายด้วยอัตราจริง
- `lottoYear`, `eggYear` (เหตุการณ์หายากระดับ "ไข่อีสเตอร์" 12 แบบ เช่น `nobel`, `oscar`, `comet`, `dino` แต่ละชีวิตได้ไม่เกินอย่างละครั้ง)
- `rareYear`: อาชีพพิเศษ เช่น นักกีฬา ไอดอล นักเล่นเกมโปร ตามด้วย `sickYear`, `lawYear`, `divorceNow` เป็นต้น

### 2.3 History (`HIST` ประมาณ 177 รายการ) และ economic era
```js
{ id:'moon', c:'*', y:1969, p:0.9, t:L`มนุษย์เหยียบดวงจันทร์…`, f:L`ราว 600 ล้านคนดูถ่ายทอดสด (NASA)` }
```
เลือกได้ว่าจะเกิดในปีใดระหว่าง 1950 ถึง 2026 (`ERA_Y0..NOW_Y`) จากนั้นเหตุการณ์โลกและวิกฤตเศรษฐกิจของประเทศนั้นจะถูก queue เข้ามาตามปีจริง ทำให้ชีวิตที่เกิดปี 1960 กับปี 2000 ในประเทศเดียวกันดำเนินไปไม่เหมือนกัน

### 2.4 Decision (`DEC` ประมาณ 147 ชนิด รวม `SMALL` 15 และ `HUM` 8)
```js
temper: { build: p => ({ title, body, fact, choices:[{k:'cur',label,sub}, …] }),
          apply: (k,p,extra) => { …; return {t, k, f, post} } , ok: p => bool }
```
- มี **2 แหล่ง** ที่ทำให้ decision ขึ้น:
  - (ก) `scheduledDecisions()` ซึ่งเกิดตามจังหวะชีวิตหรือ queue ใน flags เช่น อายุ 2 ปีเลือกนิสัย (`temper`), อายุ 6 ปีเข้าเรียน, เรียนจบแล้วต้องเลือก `school2/college/afterUni/job`, เกษียณ, พินัยกรรม, ลูกจะแต่งงาน, คู่ชีวิตเจอวิกฤต และอื่นๆ
  - (ข) event ที่ยิงเข้ามากลางปี เช่น ตกงานแล้ว queue `'job'` เข้ามา
- **SMALL** (เลือกเรื่องเล็ก): ช่วงอายุ 7–64 มีโอกาสขึ้น 9% ต่อปี มี gap 5 ปี และจะเลือกตัวที่ "ยังไม่เคยเจอในชีวิตก่อนๆ" ก่อน
- **HUM** (ช่วงเวลาที่เป็นมนุษย์): อายุ 16 ปีขึ้นไป โอกาส 45% มี gap 6 ปี ทั้งชีวิตได้ไม่เกิน 4 ครั้ง ใช้กติกา fresh-first ข้ามชีวิตแบบเดียวกัน

## 4. Decision moment, timer, timeout

- **ค่า default ไม่มี countdown** เมื่อ decision ขึ้น `S.pending` จะถูกตั้งค่า และ `tick()` หยุด จนกว่าผู้เล่นจะเลือก มีปุ่ม "วางไว้ก่อน ▾" ให้ย่อ modal ลงไปดู feed ได้
- โหมด **Auto** (ผู้เล่นเปิดเองด้วยปุ่ม "ให้ตัดสินใจอัตโนมัติตั้งแต่นี้"):
  ```js
  dur = (v.q ? 9 : clamp(bodyChars/9, 5, 14)) * (S.speed >= 16 ? 0.5 : 1);  // วินาที คิดจากความยาวข้อความ
  k = autoChoice(pd)   // เลือกตามนิสัยหรือแนวโน้มของตัวละคร (leanChoice) แล้ว highlight ปุ่มนั้นพร้อมแถบ progress
  ```
  ถ้าผู้เล่นแตะ modal countdown จะหยุด (`stopAuto`) เมื่อหมดเวลาเกมจะเลือก `autoChoice` ให้
- จำนวนตัวเลือกส่วนใหญ่ 2–4 ตัว มีแบบ chip group ด้วย (`c.g`) ใช้กดเลขบนคีย์บอร์ดเลือกได้ แต่ละตัวเลือกมี `sub` บอกผลไว้ล่วงหน้า เช่น "ความสัมพันธ์ +4" หรือ "ประมาณ 1,200 บาท"
- **SAME_WAY**: decision ที่เกิดซ้ำได้ (ลูกเข้ามหาลัย, ญาติขอยืมเงิน, ส่งเงินกลับบ้าน ฯลฯ) จะจำคำตอบเดิมไว้ใน `S.flags.way` แล้วตอบให้เงียบๆ (`q:1`) ถ้าเงื่อนไขยังเหมือนเดิม เช่น เงินยังพอ ถ้าเงื่อนไขเปลี่ยนจะกลับมาถามใหม่
- **PLAIN**: decision ที่ความน่าจะเป็นต่ำกว่า 0.2 หรือสูงกว่า 0.8 จะสุ่มตอบให้โดยไม่ถาม
- **Reflect** ที่อายุ 5/15/30/50/70: หยุดชั่วคราวให้ผู้เล่นเขียนบันทึกสั้นๆ แล้วข้อความนี้ไปปรากฏในฉากจบ ปิดได้
- ถ้าเป็นเด็กอายุต่ำกว่า 13 decision เรื่องสงครามจะให้ "พ่อแม่ตัดสินใจแทน" (`WAR_KID_A = 13`)

## 5. Death และอายุขัย

- **Life table จริงต่อประเทศและเพศ** (`lifeTable`): ใช้ e0 ซึ่งคำนวณจาก `c.le ± gap` อัตราตายทารก `im` และ `u5` แล้ว fit Gompertz–Makeham (`A + B·e^{g·x}`) ด้วย binary search บน B จนได้ e0 ตรงกับข้อมูลจริง ได้ `q[x]` สำหรับอายุ 0–110 ปี
- **ทอยตายทุกปี** ใน `endYear`:
  ```js
  q = lt.q[age]; m = 1;
  m *= exp((expHealth(a) - off - S.st.hl) * 0.03);   // stat สุขภาพเทียบกับค่าคาดของอายุ
  m *= exp(-g*(ฐานะ-3))/norm;                         // ฐานะหรือรายได้ (gradient ต่างตามภูมิภาค)
  smoker 1.7, alc 1.5, drug 2, prison 1.3, refugee 1.15, โรคที่ไม่รักษา 1.3/ตัว, อยู่คนเดียว/สังคมน้อย ≤1.35 …
  if (a>=85) m = m^(…)   // ตัวคูณส่วนบุคคลถูกบีบลงในวัยชรา
  p = 1 - (1-q)^clamp(m, 0.25, 9)
  ```
  ผลคือ ค่าเฉลี่ยของผลลัพธ์จะตรงกับอายุขัยจริงของประเทศ แต่การกระทำของผู้เล่นขยับอัตราเสี่ยงได้ประมาณ 0.25 ถึง 9 เท่า
- **สาเหตุการตาย** ได้จาก `causeWeights(c, age, sex)`: เริ่มจากตาราง GBD ตามภูมิภาคและช่วงอายุ (`CT[region][band]`) แล้วปรับด้วยข้อมูลประเทศ (HIV, มาลาเรีย, ฆาตกรรม, ถนน, สงคราม, OD) ปรับตามเพศ และปัจจัยส่วนตัว (สูบบุหรี่ไปทาง มะเร็ง/COPD, ความดันไปทาง หัวใจ/สโตรก, ความเสี่ยงอาชีพ `JOBS[].risk`, มอเตอร์ไซค์ไปทาง ถนน) สาเหตุมีประมาณ 33 แบบ (`CAUSE`)
- ไม่ได้ตายทันทีทุกกรณี: มะเร็งที่ตรวจคัดกรองพบอาจรอด (`canSvStart`) และโรคเรื้อรังจะเข้าสู่ **terminal phase** ก่อน (`termStart`/`termYear`) ทำให้มีช่วงใกล้ตายที่เล่าเรื่องได้
- ระบบย่อยฆ่าตัวละครได้โดยตรงด้วย `die('war', label)` เช่น สงคราม ภัยพิบัติ ความรุนแรง และมีเพดานอายุ 122 ปี
- `die()` บันทึก `share` ไว้ด้วย คือสาเหตุนี้คิดเป็นกี่ % ของการตายในช่วงอายุนั้นของประเทศ เพื่อใช้แสดงในใบมรณบัตร

## 6. Stat และระบบอื่นที่สร้างความหลากหลาย

- **Stat 4 ตัว** (0–100): `hl` สุขภาพ, `h` ความสุข, `sm` ความรู้, `so` สังคม ไม่ได้บวกลบตรงๆ แต่ **ค่อยๆ ไหลเข้าหาค่าเป้าหมาย** ทุกปี เช่น `hl += (target - hl) * 0.25` โดย target คำนวณจากอายุ ฐานะ การสูบบุหรี่ จำนวนโรค การเป็นผู้ลี้ภัย และเวลาที่ focus สุขภาพ ผลคือ event ให้เพียงแรงกระแทกชั่วคราว (`eff({h:3})`) ส่วนแนวโน้มระยะยาวถูกกำหนดด้วยโครงสร้างชีวิต
- **Focus** คือการควบคุมแบบต่อเนื่องเพียงอย่างเดียวของผู้เล่น ชุดตัวเลือกเปลี่ยนตามช่วงชีวิต (`focusOptions(stage)`):
  - เด็กวัยเรียน: เรียน / เล่น / ช่วยบ้าน / กีฬา / งานอดิเรก
  - วัยทำงาน: งาน / สมดุล / ครอบครัว / สุขภาพ / พัฒนาตัวเอง / งานอดิเรก
  - วัยชรา: ครอบครัว / สุขภาพ / ฝึกสมอง / ศาสนา / พักผ่อน

  เวลาที่ตั้ง focus แต่ละแบบในปีนั้นถูกนำมาถ่วงผลตอนสิ้นปี (`S.fT`) และสะสมเป็น `S.stats.fY` ซึ่งต่อมาถูกใช้เขียนคำไว้อาลัย เช่น "คนที่ทำงานอย่างขยันมาทั้งชีวิต" ถ้า focus งาน 12 ปีขึ้นไป
- **กำเนิด** (`newLife`): ประเทศสุ่มถ่วงด้วยการเกิดจริง (`c.b`) แล้วสุ่มต่อเป็นทอดๆ:
  - เพศ (ใช้ sex ratio ของประเทศ)
  - ศาสนา, กลุ่มชาติพันธุ์, วรรณะ, ราชวงศ์
  - ฐานะครอบครัว q 1–5, เมืองหรือชนบท
  - ชื่อตาม cluster ภาษาและศาสนา
  - อายุพ่อแม่ (อิงอายุเฉลี่ยตอนมีลูกคนแรกและช่องว่างอายุคู่สมรสของประเทศ)
  - จำนวนพี่น้อง (Poisson จาก TFR), พ่อไม่อยู่, ปู่ย่าตายาย, อาชีพพ่อแม่
  - talent, การรับบุตรบุญธรรม, foster care, HIV แต่กำเนิด, ความพิการ, คลอดก่อนกำหนด

  ทั้งหมดนี้รวมกันเป็น "เมล็ดเรื่อง" ที่ไม่ซ้ำกันตั้งแต่ปีแรก
- อาชีพ 69 แบบ (`JOBS`: ภาคเศรษฐกิจ, ระดับ percentile รายได้ lo/hi, ภูมิภาคที่มีอาชีพนี้, ความเสี่ยงต่อสาเหตุการตาย) รายได้ใช้ log-normal ตาม Gini ของประเทศ (`incomeAt(c, pct)`)
- ระบบที่มีอยู่: ครอบครัวและความสัมพันธ์ (คู่ชีวิต, ลูก, หลาน, เหลน, การหย่าและสิทธิ์เลี้ยงลูก), ย้ายประเทศ/ลี้ภัย, การศึกษาและสอบ, ทหารเกณฑ์, คุก/ประวัติอาชญากรรม, การลงทุน/บ้าน/เช่า/ภาษีมรดก, สัตว์เลี้ยง (ตั้งชื่อตามประเทศ), ศาสนา/การเปลี่ยนศาสนา, ความพิการ, สุขภาพจิต, ยาเสพติด/สุรา, หวย, โครงเรื่องเฉพาะ เช่น ไอดอล K-pop / เกาหลีเหนือ / โรฮิงญา
- **Companions**: `makeCompanions(4)` จำลองคนอีก 4 คนที่ "เกิดในวินาทีเดียวกัน" แบบ headless (`choose(autoChoice)` วนจนตาย) แล้วแจ้งใน feed ตามอายุที่แต่ละคนตาย เช่น "คนจากประเทศ X ที่เกิดวินาทีเดียวกับคุณเสียชีวิตแล้วตอนอายุ N (สาเหตุ)" และนำมาเทียบในหน้าสุดท้าย
- Milestone ที่อายุ 1/5/15/30/50/65/80/90/100: แสดง "เด็กที่เกิดปีเดียวกันในประเทศคุณยังมีชีวิตอยู่ราว X%" (คำนวณจาก cohort survival)

## Apply to Tower of Fate

ตารางนี้แมปกลไกที่ควรยกมาใช้ เข้ากับโครงของ Tower (ชั้นที่เดินเอง = ปี, key moment = decision, fate floor = อายุขัย)

### A. Auto-flow floors (1 ชั้น = 1 "ปี")
1. **วางตารางชั้นล่วงหน้าแบบ `planYear`**: พอเริ่มชั้นใหม่ให้ queue feed event 2–3 ชิ้นไว้ที่ตำแหน่งเวลา `0.08 + (i + rnd*0.8)/n * 0.86` และ key moment ไม่เกิน 2 ครั้งต่อชั้น ค่อยยิงตอน `t` ข้ามตำแหน่งนั้น จังหวะที่ jitter แบบนี้ไม่ซ้ำกันทุกชั้น
2. **คำนวณความยาวชั้นจากเวลารวมที่ต้องการ**: `floorSec = clamp(targetMinutes*60 / expectedFloors, 12, 120)` แล้วให้ปุ่มความเร็ว 1/2/4/8/16× และหยุดเวลาเฉพาะตอนมี key moment
3. **Focus แทนการกดตลอดเวลา**: ให้ผู้เล่นเลือกท่าทีประจำชั้นได้ทุกเมื่อ เช่น โจมตี / ระวังตัว / หาของ / พักฟื้น เก็บสัดส่วนเวลาที่ใช้แต่ละท่าทีไว้ แล้วนำไปถ่วงผลตอนจบชั้น ชุดตัวเลือกเปลี่ยนตามช่วงความลึกของหอ
4. **Stat ค่อยๆ ไหลเข้าหาเป้า** แทนการบวกลบตรงๆ: ใช้ `stat += (target - stat) * 0.25` ให้ event เป็นแรงกระแทกสั้นๆ ส่วนแนวโน้มระยะยาวมาจาก build และ focus

### B. Key moments
5. **Default คือหยุดรอ ไม่มี timer** และมีโหมด Auto ให้เปิดเอง ใช้ countdown `clamp(ความยาวข้อความ/9, 5, 14)` วินาที (ลดครึ่งที่ 16×) หมดเวลาแล้วเลือกตามนิสัยของฮีโร่ (`autoChoice`) highlight ปุ่มที่จะถูกเลือกไว้ และหยุด countdown เมื่อผู้เล่นแตะจอ
6. **SAME_WAY และ PLAIN**: key moment ที่เกิดซ้ำได้ เช่น ร้านค้าหรือคำขอของ NPC ให้จำคำตอบเดิมแล้วตอบเงียบๆ ถ้าเงื่อนไขยังเหมือนเดิม ส่วนตัวที่ผลชัดอยู่แล้ว (p<0.2 หรือ p>0.8) ให้สุ่มตอบเลย ผู้เล่นจะเหลือแต่การตัดสินใจที่มีน้ำหนักจริง
7. **ตัวเลือกบอกผลล่วงหน้าใน `sub`** เช่น "HP +4", "ประมาณ 120 ทอง" และมี `fact`/บริบทสั้นๆ 1 บรรทัดใต้หัวข้อ
8. **Follow-up queue ผ่าน flags**: ผลของ key moment ตั้ง flag เช่น `debtQ`, `rivalAt = floor+5` แล้ว `scheduledDecisions()` ของชั้นต่อๆ ไปหยิบขึ้นมา ทำให้เรื่องเชื่อมกันข้ามหลายชั้น

### C. Fate floor = lifespan
9. **ใช้ hazard table แทนการสุ่มชั้นตายครั้งเดียว**: มี `q[floor]` แบบ Gompertz (`A + B·e^{g·floor}`) แล้วปรับ B ด้วย binary search ให้ค่าเฉลี่ยชั้นตายตรงกับเป้าที่ balance ไว้ (ตอนนี้ median ราว 47) ทุกชั้นทอย `p = 1 - (1-q)^clamp(m, 0.25, 9)` โดย m เป็นตัวคูณจาก HP/stat เทียบค่าคาดของชั้นนั้น, คำสาป, ของติดตัว, การอยู่ลำพัง (เทียบได้กับ `tiesK`) ผลคือค่าเฉลี่ยคงที่แต่ผู้เล่นรู้สึกว่าตัวเองมีผลต่อชะตา
10. **สาเหตุการตายสุ่มถ่วงน้ำหนักตามโซนและ build** (`causeWeights`) และควรมีช่วง terminal ก่อนตายสำหรับสาเหตุแบบ "ค่อยเป็นค่อยไป" เช่น คำสาปลุกลาม ให้มี 1–3 ชั้นสุดท้ายที่เล่าเรื่องได้ ส่วนสาเหตุแบบ "กะทันหัน" (บอส กับดัก) ให้ตายทันที
11. **Milestone** ที่ชั้น 1/5/15/30/50/65/80/90/100: แสดง "นักผจญภัยรุ่นเดียวกันเหลือรอดราว X%" คำนวณจาก l(x) ของ table เดียวกัน

### D. Events/content
12. **Schema ของ event**: `{id, a:[floorMin,floorMax], c:()=>bool, w:number|fn, gap, rep, run:()=>({t,k,f})}` เลือกด้วย `wpick` โดยตัด event ที่ใช้ในชั้นนี้แล้ว ลดน้ำหนัก event ใน `recent` (14 ตัวล่าสุด) เป็น ×0.08 (×0.5 ถ้ามี `rep`) และเช็ค `gap` กับ `flags['ev_'+id]`
13. **ใช้ `varied(key, list)`** กับบรรทัดบรรยายประจำวัน เช่น การเดินทาง การพักแคมป์ เพื่อกันบรรทัดเดิมติดกัน และตัด one-shot line ออกหลังใช้แล้ว
14. **Variant ด้วย hash**: `hash(heroName + seed + eventId) % N` เลือกฉากของ key moment เดียวกัน ภายในชีวิตเดียวได้ฉากเดิม แต่ข้ามชีวิตได้ฉากต่างกัน
15. **จำข้ามรอบ** ใน localStorage: เก็บ id ของ key moment หรือฉากหายากที่รอบก่อนเจอแล้ว รอบใหม่ให้เลือก "fresh" ก่อน แบบ `humRecent`
16. **แยกเนื้อหาเป็นชั้นๆ**: (a) feed event ทั่วไป, (b) ระบบย่อยต่อชั้น (`xxxYear`) ที่เป็น state machine เช่น ร้านค้า คู่หู คำสาป อาชีพ, (c) WARM moment (ไม่เกินชั้นละ 1 และ joy ต้องห่างกัน 5 ชั้น), (d) เหตุการณ์หายากแบบ EGGS (ได้ครั้งเดียวต่อชีวิต และเลือกตามลำดับ), (e) เหตุการณ์ "โลก" ตาม era หรือ seed ของหอ
17. **Seed เมล็ดเรื่องตั้งแต่เกิด**: ชาติกำเนิด, ฐานะ, พี่น้อง, พรสวรรค์, ข้อบกพร่อง ถูกสุ่มเป็นทอดๆ แล้วไปเปิดหรือปิดเงื่อนไข `c()` ของ event นับร้อย นี่คือแหล่งความหลากหลายที่คุ้มที่สุดต่อ 1 บรรทัดโค้ด
18. **Companions**: จำลองฮีโร่อีก 3–4 คนที่ "เข้าหอพร้อมกัน" แบบ headless ด้วย autoChoice แล้วรายงานใน feed ตอนแต่ละคนตาย เช่น "ฟ้าร้อง ผู้เข้าหอพร้อมคุณ ล้มที่ชั้น 23" และนำไปเทียบในหน้าจบ

### E. End screen
19. **ใบมรณบัตร**: ชื่อ ชั้นที่ตาย สาเหตุ พร้อม % ว่าสาเหตุนี้พบบ่อยแค่ไหนที่ระดับชั้นนั้น เทียบกับค่าเฉลี่ย และ "นักผจญภัยรุ่นเดียวกัน X% ไปได้ไกลกว่า"
20. **Montage** (`endFrames`): แบ่งเส้นทางเป็นช่วงเท่าๆ กัน หยิบ log ที่คะแนนสูงสุดของแต่ละช่วง หักคะแนนถ้าชนิดซ้ำ ใช้ `3 + floors/10` ฉาก (ไม่เกิน 8) และใส่บันทึกของผู้เล่นก่อน
21. **คำไว้อาลัยจาก focus history**: เช่น "นักรบผู้ไม่เคยถอย" ถ้า focus โจมตีตั้งแต่ 12 ชั้นขึ้นไป หรือ "ผู้พิทักษ์ที่ดูแลเพื่อนเสมอ" แล้วเติมคำพูดสุดท้ายแยกตามประเภทการตาย (กะทันหัน/ค่อยเป็นค่อยไป) และมรดก (ของ ศิษย์ ชื่อเสียง)
22. **การ์ด canvas และ `navigator.share`** พร้อมกราฟ stat ต่อชั้นจาก snapshot `years[]` ที่บันทึกตอนจบแต่ละชั้น
23. **Audio ตามช่วง**: ระบบ chiptune ที่มีอยู่แล้วสามารถเปลี่ยน register และความหนาแน่นตามช่วงชั้น (ต้น/กลาง/ลึก/ใกล้ fate) แบบ `musicStage` และ fade ลงตอนตาย
